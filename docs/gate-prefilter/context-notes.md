# 사전 필터 확대 컨텍스트 노트

작업 중 내린 결정과 이유를 이어서 적는다. 과거 기록은 지우지 않고 틀린 것은 정정을 덧붙인다.

## 2026-10-05 (착수)
- 사실: 요청은 "b"(앞선 질문의 선택지: 사전 필터에 읽기 명령 추가)다. PR #38(정적 규칙, `gate stats`)이 열려 있어 그 브랜치 위에 `feat/gate-prefilter`를 만들었고 별도 PR로 올린다.
- 결정: 평가 세트로는 효과를 주장하지 않는다. 세트의 `grep`·`docker ps`·`kubectl get pods` 항목은 내가 모델의 오류를 보고 있는 명령이라 사전 필터에 넣고 점수가 오르는 것은 구성상 당연하다. 효과는 실제 사용 로그로 재고, 세트는 안전 회귀 방지(ask·deny 라벨 명령이 조용히 건너뛰어지지 않음)에만 쓴다.
- 결정: `grep`을 사전 필터에 넣으면 `grep SECRET .env`가 규칙에도 안 걸리고 건너뛰어지는 새 빈틈이 생긴다. `.env` 읽기 규칙의 읽기 명령 목록에 `grep`, `rg`, `jq`를 함께 더한다.
- 사실(범위 밖 발견): 기존 사전 필터의 `git branch`는 앞부분 일치라 `git branch -D main` 같은 삭제도 건너뛴다. 이번에 고치지 않고 후속 항목으로 남긴다(사전 필터가 "인자 없는 명령"을 구분하지 못하는 구조 문제와 이어진다).
