# 사전 필터 확대 컨텍스트 노트

작업 중 내린 결정과 이유를 이어서 적는다. 과거 기록은 지우지 않고 틀린 것은 정정을 덧붙인다.

## 2026-10-05 (착수)
- 사실: 요청은 "b"(앞선 질문의 선택지: 사전 필터에 읽기 명령 추가)다. PR #38(정적 규칙, `gate stats`)이 열려 있어 그 브랜치 위에 `feat/gate-prefilter`를 만들었고 별도 PR로 올린다.
- 결정: 평가 세트로는 효과를 주장하지 않는다. 세트의 `grep`·`docker ps`·`kubectl get pods` 항목은 내가 모델의 오류를 보고 있는 명령이라 사전 필터에 넣고 점수가 오르는 것은 구성상 당연하다. 효과는 실제 사용 로그로 재고, 세트는 안전 회귀 방지(ask·deny 라벨 명령이 조용히 건너뛰어지지 않음)에만 쓴다.
- 결정: `grep`을 사전 필터에 넣으면 `grep SECRET .env`가 규칙에도 안 걸리고 건너뛰어지는 새 빈틈이 생긴다. `.env` 읽기 규칙의 읽기 명령 목록에 `grep`, `rg`, `jq`를 함께 더한다.
- 사실(범위 밖 발견): 기존 사전 필터의 `git branch`는 앞부분 일치라 `git branch -D main` 같은 삭제도 건너뛴다. 이번에 고치지 않고 후속 항목으로 남긴다(사전 필터가 "인자 없는 명령"을 구분하지 못하는 구조 문제와 이어진다).

## 2026-10-05 (구현과 실제 로그 측정: 목록 확대는 안전하지만 실사용 효과는 거의 없다)
- 사실(구현): `.env` 읽기 규칙에 `grep`·`rg`·`jq`를 먼저 더했고(ask 20→23개), 기본 사전 필터를 12개에서 39개로 늘렸다(읽기 전용 명령: `grep`, `rg`, `jq`, `tree`, `file`, `stat`, `du`, `df`, `ps`, `whoami`, `date`, `uname`, `echo`, `docker ps`, `docker images`, `kubectl get pods|nodes|services|deployments|namespaces`, `git rev-parse|ls-files|blame|shortlog|describe`, `git stash list`, `git remote -v`). 표 테스트를 먼저 써서 읽기 명령 27개가 건너뛰어지지 않는 빨강을 확인한 뒤 구현했다. 안전 회귀 방지 검사(네 세트의 ask·deny 라벨 명령이 규칙·사전 필터로 조용히 건너뛰어지지 않음)는 확대 전후 모두 통과한다. 위험한 근접 사례(`grep x > out`, `find . -delete`, `kubectl get secret -o yaml`, `docker rm`, `git remote add`, `grep SECRET .env` 등)는 건너뛰어지지 않는다.
- 사실(측정, 실제 gate.log): 모델이 판정한 호출 224건 중 새로 사전 필터에 걸리는 것은 **1건(0.4%)** 이다. 그 1건(`git branch -d …`)은 내가 더한 항목이 아니라 기존 `git branch` 항목의 약점이고, 로그가 명령을 200자에서 잘라 기록해 생긴 착시일 가능성도 크다. 즉 이번 확대가 이 로그의 지연·마찰에 준 효과는 사실상 0이다.
- 사실(원인 분석): 모델이 판정한 225건 중 **79%(178건)가 셸 메타문자를 포함**하고(`|` 124, `&` 109, `>` 92, `;` 61, `(`·`)` 46, `\` 33 등), 사전 필터는 메타문자가 있는 명령을 절대 건너뛰지 않는다. 메타문자가 없는 호출은 21%(47건)뿐이고, 그중 ask·deny를 받은 25건은 `bash script.sh`, `git commit -F`, `sed -i`, `rm -rf /tmp/…`처럼 실제로 쓰거나 실행하는 명령이라 건너뛰면 안 되는 것들이다. 읽기 명령으로 시작하지만 메타문자 때문에 못 걸러진 호출이 31건이다(`ps … | grep`, `cat a; wc -l b` 같은 읽기 명령의 연결).
- 결론: 지연·마찰의 병목은 읽기 명령 목록의 길이가 아니라 "메타문자가 있으면 무조건 모델로"라는 규칙이다. 이 로그는 에이전트가 만든 복합 명령이 대부분이라는 점을 보여 준다(사람이 직접 치는 단순 명령이 많은 사용에서는 다를 수 있다). 효과를 내려면 "모든 조각이 읽기 전용이고 쓰기(`>`), 치환(`$(…)`, 백틱), 실행 위험이 없는 파이프·`;`·`&&` 연결"을 건너뛰는 방식으로 사전 필터의 매칭을 바꿔야 한다. 이는 안전과 직결된 설계 변경이라(따옴표 안의 `$(…)`가 치환된다는 점 등) 이번 범위 밖으로 두고 후속 후보로 남긴다.
- 사실(이번 범위 밖 발견): 기존 `git branch` 항목은 앞부분 일치라 `git branch -D main` 같은 삭제도 건너뛴다. 이번에 고치지 않았다.
- 판단: 이번 목록 확대는 안전 검사를 통과하고 `.env` 빈틈을 막았으며 단순 읽기 명령이 많은 사용(사람이 직접 치는 경우 등)에는 도움이 될 수 있지만, 이 로그에서는 효과가 없었다. 효과가 있다고 주장하지 않는다.
