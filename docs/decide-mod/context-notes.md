# decide-view 모드 결정 기록

## 목적
모델을 Clef-flash/Jev에서 Kev-4B 등으로 바꾸기 전에, `decide`의 기능(판정 결과, 게이트, 백엔드 상태)을 Claude Code 안에서 눈으로 볼 수 있게 한다.

## 결정
- 모드 하나(`decide-view`)에 네 기능을 묶는다. 상태(`$.state`)와 `gate.log` 읽기를 공유하기 때문이다.
- 읽기 전용이다. `gate.log`와 `decide` CLI 출력만 읽고 게이트 판정 로직은 건드리지 않는다.
- 모드 코드는 스킬 규칙상 `~/.claude/dev-mods/<세션id>/decide-view/`에 둔다. 저장소에는 이 문서만 둔다.
- `~`는 `$.fs`가 풀어 주지 않으므로 홈 경로가 필요한 호출은 `sh -c`로 한다.
- 게이트 토스트는 `tool.call`에서 `next(e)`를 기다린 뒤 `gate.log` 마지막 줄을 읽는다. 게이트 훅(PreToolUse)과 모드 훅의 실행 순서를 확인하지 못해, 기록이 먼저 쓰였다고 가정하지 않고 명령 문자열(앞 부분 일치)로 대조한다.
- 상태 줄 수치(2026-10-07 `decide gate stats` 기준)로 볼 때, 시간 초과 10.1%(56/552)와 local 평균 1133ms 대 typesafe 216ms는 모드가 가장 먼저 드러내야 할 값이다.

## 미확인
- `decide` MCP 서버는 이번 세션에서 ECONNREFUSED였다(데몬 꺼짐). 밴드의 실제 도구 결과 형태는 `show.rs` 테스트 입력으로만 확인했다.
- 도구 결과 객체의 정확한 모양(`result`가 문자열인지 content 배열인지)은 타입 파일로 검증한다.

## 2026-10-07 통계 패널을 막대 그래프로
- `decide gate stats` 텍스트 출력 대신 `gate.log` 최근 5000줄을 직접 집계해(`summarizeLog`) 그린다. 텍스트를 파싱하면 히스토그램에 필요한 분포를 얻을 수 없기 때문이다.
- 차트 전용 요소가 없어 `Text`의 블록 문자(`█`)와 `color`로 막대를 그린다. 판정 분포, 판정 방식, 백엔드별 지연 히스토그램(<250 … ≥2000ms), 최근 40건 스파크라인.
- 집계에서 `failure`가 있는 줄은 판정 분포와 지연에서 뺀다(데몬 시간 초과·재시작이라 판정이 없다).

## 2026-10-07 패널을 박스 드로잉·이모지로
- 머리줄(`┏━`, `┣━`, `┗━`)과 왼쪽 레일(`┃`)만 쓰고 오른쪽 테두리는 두지 않는다. 이모지 폭이 터미널마다 달라 오른쪽 선이 어긋나기 때문이다. 머리줄 폭은 `displayWidth`(한글·이모지 2칸)로 맞추고 테스트로 고정했다.
- 막대는 바탕(`░`)까지 그려 길이를 일정하게 둔다(`track`). 이모지는 VS16이 필요한 것(⚙️, ⏱️)을 피하고 단일 코드포인트(📊 🟢 🟡 🔴 🧭 🤖 🧱 🔎 🚧 ⏳ ⚡ 🐢 📈)만 쓴다.
- 버그를 고쳤다. 실패(72건)와 사전 필터(12건) 줄은 `verdict`가 null이라 처음에는 집계에서 통째로 빠졌다. 실제 로그와 대조해 `decide gate stats`의 방식별 건수와 맞췄다.

## 2026-10-07 패널을 /context-bar 모양으로
- 참고 이미지(`/context-bar`)처럼 둥근 테두리 상자, 머리줄(제목 왼쪽, 요약·배지 오른쪽), 누적 막대 한 줄, 색 사각형(■) 범례 격자로 바꿨다. 이전의 줄 기반 막대와 `displayWidth`, `track`, `panelLines`는 쓰지 않아 지웠다.
- 테두리는 `Box borderStyle="round"`에 맡겼다. 직접 그리면 이모지·한글 폭 때문에 오른쪽 선이 어긋나므로 엔진이 계산하게 한다.
- 누적 막대(`segments`)는 비율대로 칸을 나누되 합이 정확히 width, 0이 아닌 항목은 최소 1칸이다. 사용 색은 `COLORS`(hex 문자열)다. hex가 이 엔진의 `Color`에서 실제로 그려지는지는 확인하지 못했다.
- 구역 3종: 게이트 판정(허용 비율 배지), 판정 방식, 백엔드별 지연(구간 누적 막대).

## 2026-10-07 지연 구역을 하나로
- 백엔드별 지연 구역(local, typesafe)을 `⏳ 지연` 한 구역으로 합쳤다. 막대와 `p90`은 두 백엔드의 모델 판정 표본 전체이고, 백엔드별 평균·p90·최대와 스파크라인은 아래 줄로 남겼다.
- 주의. 두 백엔드는 지연 특성이 달라(typesafe 약 220ms, local 약 1150ms) 합친 분포는 두 봉우리가 섞인다. 비교는 아래 백엔드별 줄로 한다.

## 2026-10-07 패널 최상단에 백엔드·엔드포인트
- 표시하는 값은 데몬이 실제로 쥔 설정이다. `ps eww`로 실행 중 데몬의 `DECIDE_BACKEND`, `DECIDE_TYPESAFE_URL`, `DECIDE_LOCAL_REPO`, `CLEF_WEIGHTS`를 읽고, 없으면 `~/.config/decide/config.toml`, 그다음 기본값 순이다(`resolveRoute`). 이 순서는 `backend.rs`의 `resolved_typesafe_url`(환경변수, 설정 파일)과 같다. 백엔드를 키 유무로 고르는 규칙은 CLAUDE.md의 설명이고 코드로 대조하지는 않았다.
- 비밀은 화면에 내지 않는다. `TYPESAFE_API_KEY`는 값이 아니라 존재 여부(개수)만 읽고, URL의 `user:pass@`는 지운다.
- 한계. 데몬이 꺼져 있으면 환경변수를 읽을 수 없어 config.toml과 기본값으로만 추정하고 `데몬 ○ 꺼짐`을 함께 보인다. 이 경우 실제 새 데몬이 쥘 환경과 다를 수 있다.

## 2026-10-07 막대를 얇게
- 누적 막대 문자를 `█`(전체 블록)에서 `━`(굵은 가로선)으로 바꿨다. 한 줄 높이의 가는 선으로 그려지고 색과 칸 수 계산은 그대로다. 더 두꺼운 중간 두께가 필요하면 `▄`(아래 반 블록)를 쓴다.

## 2026-10-07 지연은 선택된 백엔드 한 줄로
- 지연 구역은 지금 선택된 백엔드(패널 최상단에 표시한 값)의 모델 판정 표본만 보인다. 막대, p90, 아래 한 줄 `n=… · 평균 … · p90 … · 최대 …`이 모두 그 백엔드 기준이다. 백엔드별 줄과 스파크라인은 뺐다(`sparkline`, `recent`, 통합 집계 `all`도 함께 지웠다).
- 그 백엔드의 기록이 없으면 지연 구역을 만들지 않는다. 백엔드끼리 비교하려면 모델을 바꾼 뒤 이 구역의 수치를 이전 값과 대조한다.

## 2026-10-07 지연은 구간별 얇은 막대로
- 지연 구역의 누적 막대와 범례를 구간별 한 줄 막대(히스토그램 행)로 바꿨다. 행은 `구간 ━━━… 건수 비율`이고 가장 긴 막대가 `width`칸이다. 누적 막대는 판정 분포와 판정 방식에만 쓴다. 누적으로는 구간 길이 차이가 읽히지 않아서다.

## 2026-10-07 지연은 최근 5분 평균 게이지, 새로고침 버튼 제거
- 지연 구역을 구간별 막대에서 막대 하나로 줄였다. 길이는 최근 5분 평균 지연 ÷ 2000ms(데몬 시간 초과)이고, 색은 평균의 등급이다. 초록 300ms 미만, 파랑 800ms 미만, 노랑 1500ms 미만, 빨강 그 이상이다. 기준값은 실측(typesafe 약 220ms, local 약 1150ms)을 보고 정한 임의 값이며 바꿀 수 있다(`LEVELS`).
- 5분 창은 `gate.log`의 `ts`(초)와 `$.clock.now()`로 거른다. 판정 분포·방식은 최근 5000줄 전체, 지연만 5분 창이다.
- 새로고침 버튼을 없애고, 패널을 처음 연 뒤 5초마다 `gate.log`와 라우팅을 다시 읽는다. 패널을 닫는 이벤트를 몰라 세션이 끝날 때까지 폴링한다(프로세스 두 개 5초마다).
- 모델 판정이 5분 안에 없으면 `최근 5분 기록 없음`을 보인다. 훅 게이트는 읽기 전용 명령을 사전 필터로 건너뛰므로 조용한 시간대에는 흔하다.

## 2026-10-07 화면 라벨을 영문으로
- 패널, 상태 줄, 토스트, 밴드에 보이는 문자열을 모두 영문으로 바꿨다(`decision path`, `static rule`, `prefilter`, `model`, `fail-open`, `latency`, `avg 5m`, `daemon`, 출처 `env`/`config.toml`/`default`/`by API key`). 소스 주석과 테스트 제목은 CLAUDE.md 규칙대로 한글이다.
- 로그에 남은 한글(데몬 시간 초과 사유 등)은 이 모드가 화면에 내지 않는다. `failure`는 유무만 센다.

## 2026-10-07 구역마다 박스
- 바깥 상자 하나를 없애고 backend, gate, decision path, latency를 각각 둥근 테두리 상자로 나눴다. backend 상자는 머리줄 오른쪽에 `daemon ●`(초록)/`○ down`(빨강)을 두고, 백엔드와 출처, 엔드포인트와 출처를 한 줄씩 보인다. 모든 상자는 같은 폭(`width + 4`)이다.

## 2026-10-07 플러그인 이름을 decide로
- 토스트 박스 제목은 엔진이 플러그인 이름으로 붙이므로(`$.ui.toast`는 `timeoutMs`만 받는다) 제목을 바꾸려면 플러그인 이름을 `decide-view`에서 `decide`로 바꿔야 한다. 폴더(`~/.claude/dev-mods/<세션id>/decide/`), `plugin.json`의 `name`, 상태 키(`atom`의 `plugin`, 타입 계약)를 함께 바꿨다. 이 문서의 앞부분 `decide-view`는 이전 이름이다.
- 토스트 박스 색은 엔진이 그리고 `ToastOptions`에 색이 없어 모드에서 바꿀 수 없다. 패널 박스의 `borderColor`(현재 `subtle`)는 모드가 정한다.

## 2026-10-07 토스트 진단과 색
- 토스트가 안 보이던 원인 조사. 임시 진단 로그로 Bash 훅이 끝까지 돌아 토스트 문구(`gate ask · rule grep *.env *`)를 만들고 `$.ui.toast`를 부르는 것까지 확인했다. 그래서 모드 논리는 정상이고, 토스트 표시 쪽 문제다. 토스트는 스크롤백 모드에서 알림줄 한 줄로 4초만 뜨기 때문에(문서), 표시 시간을 10초로 늘렸다. 이것이 원인인지는 미확인이다.
- 별개의 버그를 찾아 고쳤다. 마지막 로그 줄이 사전 필터·규칙 줄이면(`verdict`나 `backend`가 비어 있다) 상태 줄 갱신이 `null`로 덮어써 백엔드 표시가 사라졌다. 이제 상태 줄은 `backend`가 있는 마지막 줄을, 토스트 대조는 마지막 줄을 따로 읽는다.
- 토스트 글자 색은 엔진 API에 없어 패널과 같은 색의 점으로 나타낸다(🟡 ask, 🔴 deny). allow와 판정 없음은 띄우지 않는다.
- 진단 코드는 지웠다.

## 2026-10-07 토스트 점을 작은 원으로
- 토스트의 색 점을 이모지(🟡 🔴, 2칸 크기)에서 작은 원 `●`로 바꾸고, 색은 24비트 ANSI 코드(`ESC[38;2;R;G;Bm`)로 입혔다. 토스트가 ANSI를 해석하는지는 확인하지 못했다. 코드가 그대로 보이면 코드를 지우고 `●`만 쓴다(`gateToast`의 `DOTS`).
