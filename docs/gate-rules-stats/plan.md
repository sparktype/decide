## 설계 A. 정적 규칙 계층
**평가 순서(바뀌는 부분).** 지금은 `사전 필터 → 모델`이다. 이렇게 바꾼다.

```text
deny 규칙 → ask 규칙 → 사전 필터(통과) → 모델
```

규칙이 걸리면 모델을 부르지 않고 그 판정으로 끝난다. 규칙은 모델이 틀릴 수 있는 곳을 확정적으로 막는 용도이고, 모델의 판단을 대체하지 않는다(규칙에 안 걸린 명령은 그대로 모델이 판정한다).

**패턴 문법.** 글롭이며 `*`만 와일드카드다(정규식 아님, `\*`는 글자 별표). 패턴 끝의 ` *`는 인자가 없는 경우도 맞춘다. 명령은 공백을 하나로 접고 대소문자를 무시해 비교한다. 패턴은 명령 전체와, `&&`·`||`·`;`·줄바꿈으로 나눈 각 조각(앞의 `sudo` 등과 `NAME=값` 대입은 벗김, 따옴표 안은 나누지 않음)에 건다. 파이프는 나누지 않는다. (처음 계획은 "복합 명령 전체에만"이었으나 `cd x && sudo rm -rf /`를 패턴마다 변형 없이 잡고 따옴표 안의 글자 오탐을 줄이려고 조각 단위를 더했다. 노트 참고.) 이유는 Claude Code의 권한 규칙(`Bash(git push *)`)과 비슷해 익숙하고, 의존성 없이 몇 줄로 구현되며, 사용자가 읽고 고칠 수 있기 때문이다.

**설정.** `gates.bash-risk.deny_patterns`, `gates.bash-risk.ask_patterns`(문자열 배열).
- 내장 기본값 → 사용자(`~/.config/decide/gates.json`) → 저장소(`./.decide/gates.json`) 순으로 덮는다.
- 사용자 층은 목록을 통째로 바꿀 수 있다(기본 규칙을 뺄 수도 있다). **저장소 층은 적은 항목을 기존 목록에 더하기만 한다**(합집합, 더 엄격한 쪽). 저장소는 기본 규칙을 다시 적을 필요도 뺄 방법도 없다. (처음에는 "기존 항목을 모두 지킨 상위 집합"이어야 허용하려 했으나, 기본 목록이 비어 있지 않게 되자 저장소가 규칙 하나를 더하려면 기본 규칙을 전부 다시 적어야 해서 합집합으로 바꿨다. 노트의 A-5 항목 참고.)
- `decide gate --show bash-risk`가 두 목록과 값마다의 출처를 보여 준다. `--json`의 `config`는 그대로 복사해 쓸 수 있다.

**기본 목록의 원칙(구체 항목은 구현 단계에서 확정).**
- `deny`는 되돌릴 수 없고 거의 항상 의도하지 않은 것만. 루트·홈 전체 삭제, 디스크 장치에 쓰기, 파일시스템 포맷, 포크 폭탄, 원격 스크립트를 셸에 파이프, 데이터베이스 통째 삭제.
- `ask`는 의도일 수 있지만 확인이 필요한 것. 강제 푸시, `git clean`, 되돌리기 어려운 `git reset --hard`, 자격증명 파일 접근(`~/.ssh`, `.aws/credentials`, `.env` 등).
- 특정 평가 세트의 명령을 그대로 옮겨 적지 않는다. 기본 목록은 일반 지식으로 쓰고, 오탐은 실제 로그와 near-miss 세트로 잰다.

**출력과 로그.** 규칙 판정은 `Kind::Rule { verdict, pattern }`이다. 화면에는 "정적 규칙: <패턴> (모델 호출 없음)"으로 근거를 보이고, 감사 로그에는 `rule` 필드를 더한다(`backend`·`latency_ms`는 비움). 감사 모드에서는 지금처럼 막지 않고, enforce에서는 `deny`/`ask`가 `permissionDecision`으로 넘어간다.

## 설계 B. `decide gate stats`
`~/.cache/decide/gate.log`를 집계해 보여 주는 읽기 전용 명령이다.

```text
decide gate stats [--since 24h|7d|all] [--json]
```

출력 항목: 기간과 건수, 판정 방식별 건수(규칙 / 사전 필터 / 모델 / 실패·통과), 판정 분포(`allow`·`ask`·`deny`와 `ask` 비율), 지연(평균, 중앙값, p90, p95, 최대를 백엔드별로), 모델이 필요한 호출 대비 제한 시간 초과 비율, 낮은 확신 구간(최고 확률이 `confidence` 미만이라 `ask`가 된 건수), 실패 사유별 건수, 규칙 적중 상위 패턴.
- 집계는 순수 함수(`summarize`)로 만들어 고정된 로그로 테스트한다. 깨진 줄은 건너뛰고 건수만 알린다.
- 지연은 "백엔드 구간만"이라는 주석을 붙인다(훅 프로세스와 소켓 오버헤드 약 0.2초는 별도).
- 해석이나 추천은 내지 않는다. 숫자만 낸다.

## 검증 계획
1. 새 평가 세트(`bash_risk_heldout3.json`, 30건)를 **규칙을 쓰기 전에** 먼저 커밋한다. 규칙에 걸려야 하는 명령, 걸리면 안 되는 near-miss(`rm -rf ./build`, `git push --force-with-lease`, `cat .env.example`, 파일 대 파일 `dd`), 일반 명령을 섞는다.
2. **오탐 검사**: 실제 `gate.log`의 명령 전체와 기존 세 세트의 정상(allow 라벨) 명령에 규칙을 돌려, 정상 명령에 규칙이 걸린 건수를 센다. 목표는 0건이다. 걸리면 기본 패턴을 고친다.
3. **효과 측정**: heldout3에서 모델 단독과 규칙+모델을 한 번씩 비교한다(정답 수, 정상→deny, 위험→allow, 모델 호출 수).
4. stats는 실제 `gate.log`에서 임시 스크립트 결과(로컬 평균 994ms 등)와 같은 값이 나오는지 대조한다.
5. 기본 테스트 스위트 전체 통과, README 점검 스크립트 통과.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 규칙 오탐으로 정상 명령이 `deny`/`ask` | 위 오탐 검사, 기본 `deny`는 치명적인 것만, 감사 모드가 기본이라 바로 막지 않음 |
| 우회(`rm -rf "$HOME"`, 변수·치환) | 규칙은 확정적 안전망이지 완전한 방어가 아님을 문서에 명시. 모델 판정은 그대로 남음 |
| 평가 세트에 맞춘 과적합 | 기본 목록을 일반 지식으로 쓰고, 처음 보는 세트에서만 효과를 주장 |
| 복합 명령에서 부분 일치 | 글롭 앞뒤 `*`로 전체 문자열을 검사하되, 테스트로 경계를 고정 |

## 결정 대기(가정)
1. 패턴은 글롭(`*`만)으로 한다. 정규식이 필요하면 후속.
2. 강제 푸시는 `deny`가 아니라 `ask`다(실제로는 기능 브랜치에서 흔한 동작이라서). 평가 라벨의 `deny`와 다르다.
3. 저장소 설정은 규칙을 더하기만 할 수 있다.
4. `stats`의 기본 기간은 `all`이다.
5. 새 기능이므로 릴리스한다면 버전은 0.5.0(마이너)이다. 릴리스 여부는 이 작업이 끝난 뒤 따로 정한다.
