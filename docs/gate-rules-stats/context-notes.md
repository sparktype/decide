# 게이트 정적 규칙과 `gate stats` 컨텍스트 노트

작업 중 내린 결정과 그 이유를 아래에 이어서 적는다. 과거 기록은 지우지 않고, 틀린 것은 정정 항목을 덧붙인다.

## 2026-10-05 (착수, 계획 수립)
- 사실: 요청은 "1,3번 진행"이었다. 앞서 낸 1순위 추천 표의 첫째(정적 규칙 계층)와 셋째(`decide gate stats`)로 해석했다. 표에 번호가 붙어 있지는 않았다. 해석이 다르면 범위를 고친다.
- 사실: 기준은 최신 `origin/main`(`f90f8a4`, v0.4.1 + README 현행화)이다. 작업 브랜치는 `worktree-gate-static-rules`다.
- 결정: 규칙 문법은 글롭(`*`만)이다. Cargo 의존성을 늘리지 않고 몇 줄로 구현할 수 있고 사용자가 읽기 쉽다. 정규식이 꼭 필요해지기 전에는 만들지 않는다.
- 결정: 규칙은 `deny → ask → 사전 필터 → 모델` 순으로 본다. 규칙은 모델을 대체하지 않고, 모델이 틀릴 수 있는 곳을 확정적으로 막는 안전망이다.
- 결정: 강제 푸시는 `deny`가 아니라 `ask`로 시작한다. 기능 브랜치에서는 정상 동작인 경우가 많다. 이는 평가 세트의 라벨(`deny`)과 다르므로, 평가에서 이 명령이 `deny`가 아니어도 규칙 실패로 세지 않는다고 미리 적어 둔다.
- 결정: 새 평가 세트(heldout3)는 규칙을 쓰기 전에 커밋한다. 기존 세 세트는 이미 결과를 봤고, 기본 규칙을 쓰는 사람(나)도 그 세트의 명령을 알고 있어서 효과를 일반화 근거로 쓸 수 없다. 기존 세트는 오탐 검사에만 쓴다(정상 명령에 규칙이 안 걸리는지).
- 결정: 위험 평가 기준을 미리 정한다. 오탐 검사는 정상 명령에 규칙 적중 0건이 아니면 통과가 아니다. 효과 측정은 좋아졌다는 가정 없이 결과를 그대로 적는다.
- 한계: 규칙은 변수 확장(`rm -rf "$HOME"`), 인코딩, 별칭 같은 우회를 못 잡는다. 모델 판정이 그 뒤에 남아 있다는 점이 안전망이고, 규칙만으로 방어한다고 문서에 적지 않는다.
